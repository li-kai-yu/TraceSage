# 05 数据库设计规范

## 1. 基本约定

| 项 | 约定 |
| --- | --- |
| 数据库 | MySQL 8.0，库名 `tracesage` |
| 字符集 | `utf8mb4` / 排序规则 `utf8mb4_general_ci` |
| 引擎 | InnoDB |
| 表名 | 小写下划线，**单数**，按模块加前缀：`sys_user`、`trace_span`、`insight_fault_case` |
| 字段名 | 小写下划线，禁止驼峰、禁止拼音 |
| 主键 | 统一 `id bigint unsigned`，业务表用**雪花 ID**（MyBatis-Plus `ASSIGN_ID`） |
| 金额/计数 | 用 `decimal` 表达金额，用 `bigint` 表达计数 |
| 时间 | `datetime(3)` 精度到毫秒 |

## 2. 必备字段（每张业务表都要有）

```sql
CREATE TABLE sys_user (
    id            BIGINT UNSIGNED NOT NULL COMMENT '主键，雪花ID',
    username      VARCHAR(64)     NOT NULL COMMENT '登录名',
    password      VARCHAR(100)    NOT NULL COMMENT 'BCrypt 加密后的密码',
    -- 业务字段 ...
    create_time   DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
    update_time   DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3) COMMENT '更新时间',
    create_by     BIGINT UNSIGNED          DEFAULT NULL COMMENT '创建人ID',
    update_by     BIGINT UNSIGNED          DEFAULT NULL COMMENT '更新人ID',
    deleted       TINYINT(1)      NOT NULL DEFAULT 0 COMMENT '逻辑删除：0未删除 1已删除',
    PRIMARY KEY (id),
    UNIQUE KEY uk_username (username, deleted)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COMMENT = '系统-用户表';
```

> 逻辑删除字段名固定为 `deleted`，与 MyBatis-Plus 全局配置保持一致：
> `mybatis-plus.global-config.db-config.logic-delete-field=deleted`。

## 3. 索引规范

- 命名：唯一索引 `uk_{字段}`，普通索引 `idx_{字段}`，联合索引 `idx_{字段1}_{字段2}`。
- 单表索引数量 **不超过 5 个**；联合索引把区分度高的字段放前面。
- 禁止在索引列上做函数运算、隐式类型转换。
- 长文本（报错堆栈、模型输入输出）不进 MySQL 索引，放 ES 或 `TEXT` 字段。
- 唯一索引必须带上逻辑删除列（`uk_username (username, deleted)`），否则删除后无法重建同名记录。

## 4. 表结构草案（按限界上下文划分）

### 4.1 IAM 上下文（tracesage-system）

| 表 | 说明 | 关键字段 |
| --- | --- | --- |
| `sys_user` | 用户 | username、password、nickname、email、status |
| `sys_role` | 角色 | role_code、role_name |
| `sys_permission` | 权限/菜单 | perm_code、perm_type、parent_id、path |
| `sys_user_role` | 用户-角色关联 | user_id、role_id |
| `sys_role_permission` | 角色-权限关联 | role_id、perm_id |

关联表无业务字段，不继承必备字段中的审计列（只保留 `id`、`create_time`）。

### 4.2 Tracing 上下文（tracesage-system）

链路明细数据量大，**主存储放 Elasticsearch**，MySQL 只存元数据。

| 表 | 说明 | 关键字段 |
| --- | --- | --- |
| `trace_app` | 接入应用 | app_code、app_name、owner、sample_rate |
| `trace_ingest_statistics` | 采集统计（按小时聚合） | app_code、stat_hour、span_count、error_count、avg_cost |

ES 索引：

| 索引 | 说明 | 关键字段 |
| --- | --- | --- |
| `trace_{yyyyMMdd}` | 链路明细，按天滚动 | traceId、spanId、parentSpanId、appCode、serviceName、methodName、costMs、success、errorMsg、startTime |
| `trace_topology` | 服务拓扑边 | fromService、toService、callCount |

> ES 索引按天创建，通过索引模板（`trace_*`）统一 mapping，避免字段类型漂移。

### 4.3 Insight 上下文（tracesage-insight）

| 表 | 说明 | 关键字段 |
| --- | --- | --- |
| `insight_fault_case` | 历史故障案例（RAG 语料源） | case_title、symptom、root_cause、solution、app_code、tags、embedding_id |
| `insight_analysis_report` | 分析报告 | trace_id、case_ids、root_cause、confidence、report_content、status、cost_ms |
| `insight_knowledge_doc` | 知识库文档 | doc_name、doc_type、chunk_count、vector_status |

向量存储：`insight_fault_case.embedding_id` 指向向量库中的记录，
本地开发可用 ES `dense_vector` 承载，后续可平滑替换为专用向量库。

## 5. DDD 与数据库的映射

| DDD 概念 | 数据库对应 | 说明 |
| --- | --- | --- |
| 聚合根 | 主表 | 一个聚合根一张主表 |
| 实体 | 子表 | 有独立 ID，通过聚合根访问 |
| 值对象 | 内嵌列或 JSON 列 | 如 `tags` 存 JSON、`cost` 用 `decimal` |
| 领域事件 | `outbox` 表 / MQ | 需要可靠投递时用本地消息表 |
| 仓储实现 | Mapper + PO | PO 与表一一对应，Entity 与表解耦 |

**约束：PO 只加 `@TableName` / `@TableId` 等持久化注解；业务不变量写在 Entity，不写在 PO。**

## 6. MyBatis-Plus 约定

```yaml
mybatis-plus:
  mapper-locations: classpath*:/mapper/**/*.xml
  configuration:
    map-underscore-to-camel-case: true
  global-config:
    db-config:
      id-type: assign_id          # 雪花ID
      logic-delete-field: deleted
      logic-delete-value: 1
      logic-not-delete-value: 0
```

- 单表 CRUD 用 `BaseMapper`，**不写 XML**。
- 复杂查询（多表关联、聚合统计）才写 XML，放在 `resources/mapper/`，一个文件对应一个 Mapper。
- XML 中禁止写 `SELECT *`，必须显式列出字段。
- 分页统一用 MyBatis-Plus 的 `Page<T>`，不手写 `limit`。

## 7. 变更规范

- 建表与变更脚本统一放 `db/migration/`，命名 `V{版本号}__{描述}.sql`（Flyway 规范）。
- 生产环境**禁止** `DROP`、禁止直接改字段类型；新增字段必须可空或带默认值。
- 大表加索引走 `ALTER TABLE ... ALGORITHM=INPLACE`，并在低峰期执行。
- 每次变更同步更新本文档的表结构草案。
