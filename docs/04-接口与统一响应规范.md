# 04 接口与统一响应规范

## 1. URL 规范

```
/{服务前缀}/{版本}/{资源}/{动作}
   api/system/v1/users/{id}
```

| 规则 | 说明 |
| --- | --- |
| 前缀 | 网关统一前缀 `/api/{服务名}`，服务内部 Controller **不重复写服务名** |
| 版本 | 统一 `v1`，写在 `@RequestMapping("/v1/xxx")` 上 |
| 资源 | **名词复数、小写、短横线分隔**：`/users`、`/trace-spans` |
| 动作 | 尽量用 HTTP 方法表达；复杂动作才用子资源：`POST /v1/traces/{id}/analysis` |
| 禁止 | 动词出现在路径中：`/getUser` ❌ → `GET /v1/users/{id}` ✅ |

网关路由前缀与服务的对应关系：

| 网关路径 | 转发到 |
| --- | --- |
| `/api/system/**` | tracesage-system |
| `/api/insight/**` | tracesage-insight |

## 2. HTTP 方法与状态码

| 方法 | 语义 | 成功码 |
| --- | --- | --- |
| GET | 查询资源（幂等） | 200 |
| POST | 创建资源 / 执行动作 | 200 |
| PUT | 全量更新 | 200 |
| PATCH | 局部更新 | 200 |
| DELETE | 删除 | 200 |

> 统一返回 200，业务结果由响应体中的 `code` 表达，避免前端处理多套逻辑。
> 只有网关层（鉴权失败、限流）和框架层（404、500）才使用非 200 的 HTTP 状态码。

## 3. 统一响应体

```java
// com.tracesage.common.core.result.Result
public class Result<T> {
    private Integer code;       // 业务状态码
    private String message;     // 提示信息
    private T data;             // 数据
    private Long timestamp;     // 服务端时间戳，便于排查
    private String traceId;     // 链路 ID，出问题直接拿去搜链路
}
```

响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { "id": 1001, "username": "admin" },
  "timestamp": 1760000000000,
  "traceId": "8f3a1c92b7d44e10"
}
```

## 4. 业务状态码分段

| 区间 | 含义 | 示例 |
| --- | --- | --- |
| 200 | 成功 | 200 操作成功 |
| 400 ~ 499 | 客户端错误（参数/认证/权限） | 400 参数校验失败、401 未登录、403 无权限 |
| 500 ~ 599 | 服务端错误（系统异常） | 500 系统繁忙 |
| 1000 ~ 1999 | IAM 模块 | 1001 用户名已存在、1002 密码错误 |
| 2000 ~ 2999 | Tracing 模块 | 2001 链路不存在、2002 链路数据格式错误 |
| 3000 ~ 3999 | Insight 模块 | 3001 知识库为空、3002 模型调用失败 |
| 9000 ~ 9999 | 第三方/中间件 | 9001 Nacos 不可用、9002 ES 查询超时 |

```java
// com.tracesage.common.core.result.ResultCode
public enum ResultCode {
    SUCCESS(200, "操作成功"),
    PARAM_INVALID(400, "参数校验失败"),
    UNAUTHORIZED(401, "未登录或令牌已失效"),
    FORBIDDEN(403, "没有操作权限"),
    SYSTEM_ERROR(500, "系统繁忙，请稍后重试"),

    USERNAME_EXISTS(1001, "用户名已存在"),
    PASSWORD_WRONG(1002, "用户名或密码错误"),

    TRACE_NOT_FOUND(2001, "链路不存在"),

    KNOWLEDGE_EMPTY(3001, "知识库暂无匹配内容"),
    LLM_CALL_FAILED(3002, "模型调用失败");
}
```

**新增错误码必须登记在 `ResultCode` 中，禁止在业务代码里裸写魔法数字。**

## 5. 分页规范

请求统一继承分页基类：

```java
public class PageQuery {
    private Integer pageNum = 1;    // 页码，从 1 开始
    private Integer pageSize = 10;  // 每页条数，最大 100
}
```

响应统一使用 `PageResult<T>`：

```java
public class PageResult<T> {
    private List<T> records;
    private Long total;
    private Integer pageNum;
    private Integer pageSize;
    private Integer pages;
}
```

约束：
- `pageSize` 超过 100 时强制收敛为 100，防止拖库。
- 深度分页（页码 > 100）走 ES `search_after`，禁止 `from + size` 深翻。
- 列表接口不返回大字段（如完整堆栈、原始报文）。

## 6. 参数校验

- 统一使用 JSR-303 注解，Controller 入参加 `@Valid` / `@Validated`。
- 校验消息用中文，写在注解里：`@NotBlank(message = "用户名不能为空")`。
- 分组校验：新增用 `Create.class`，修改用 `Update.class`，避免写两套 DTO。
- 业务规则校验（如密码强度、状态流转合法性）不放注解，放领域层。

## 7. 异常处理

- 业务异常统一抛 `BizException(ResultCode, ...)`，由 `common-web` 的
  `GlobalExceptionHandler` 兜底转换为 `Result`。
- **禁止**在 Controller 里写 `try-catch` 把异常吞掉。
- 系统异常必须打 ERROR 日志并携带 `traceId`，对外只返回「系统繁忙」，不外泄堆栈。
- Feign 调用失败：`FeignException` 统一转换为 `BizException`，避免把底层异常透传到前端。

## 8. 接口文档（Knife4j）

- 访问地址：`http://localhost:{port}/doc.html`
- Controller 必须加 `@Tag(name = "xxx")`，方法加 `@Operation(summary = "xxx")`。
- 生产环境通过配置关闭增强模式：`knife4j.enable=false`、`knife4j.production=true`。
- DTO/VO 字段加 `@Schema(description = "xxx")`，枚举字段用 `@Schema(allowableValues = ...)`。

## 9. 安全与透传

| 头 | 说明 |
| --- | --- |
| `Authorization` | 网关校验的 JWT，格式 `Bearer {token}` |
| `X-Trace-Id` | 链路 ID。网关生成、服务内透传、日志 MDC 打印 |
| `X-User-Id` / `X-Username` | 网关鉴权后透传给下游，下游不重复解析 JWT |

- 白名单（登录、注册、健康检查）在网关配置，服务内部不做鉴权逻辑。
- 服务**只信任来自网关的** `X-User-*` 头，对外暴露端口时应确保不可绕过网关。
